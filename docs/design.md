# Data Quality Validator 設計書

## 1. 目的

CSVファイルをデータベースへ登録する前に検査し、
主キー、必須項目、日付、数値、文字数などの不備を検出する。

自治体システムのデータ移行・品質検証で得た知見をもとに作成するが、
公開リポジトリでは架空のデータと仕様だけを使用する。

## 2. 想定利用者

- CSVデータをデータベースへ移行する担当者
- データ連携処理を開発するエンジニア
- データの品質を事前確認したい担当者
- PythonによるCSV検査を学習する人

## 3. 対象範囲

最初のバージョンでは、1つのCSVファイルを検査対象とする。

### 実施する検査

1. 必須項目の空欄
2. 主キーの空欄
3. 主キーの重複
4. 日付の妥当性
5. 整数項目の形式
6. 最大文字数

### 最初のバージョンでは実施しないもの

- データベースへの登録
- 複数CSV間の整合性確認
- 外部キー検査
- Web画面
- AIによる自動判定
- 実在する個人情報の処理

## 4. 入力ファイル

### 4.1 サンプルCSV

ファイル名：

`sample/input.csv`

想定する列：

| 列名 | 内容 | 型 | 必須 | 最大長 |
|---|---|---|---|---|
| record_id | レコードID | 文字列 | 必須 | 10 |
| full_name | 氏名 | 文字列 | 必須 | 40 |
| birth_date | 生年月日 | 日付 | 任意 | 8 |
| household_size | 世帯人数 | 整数 | 任意 | - |
| remarks | 備考 | 文字列 | 任意 | 100 |

サンプルデータはすべて架空のものを使用する。

### 4.2 検査ルール

ファイル名：

`config/validation_rules.json`

CSVごとの検査条件をJSON形式で定義する。

## 5. CSVの読込方針

- 文字コードの初期値はUTF-8（BOM付きにも対応）とする
- 必要に応じてCP932を指定できるようにする
- `record_id`などの先頭ゼロを保持するため、原則として文字列で読み込む
- 空文字と空白文字を、必須検査では未入力として扱う
- 元データを自動修正せず、エラーとして報告する

## 6. 日付検査

初期バージョンで認める形式：

`YYYYMMDD`

正常例：

- `19640229`
- `20260926`

異常例：

- `19650229`
- `20261301`
- `20260931`
- `2026/09/26`
- `abcdefgh`

形式が8桁でも、実在しない日付はエラーとする。

## 7. エラー出力

出力ファイル：

`output/validation_errors.csv`

出力項目：

| 項目 | 内容 |
|---|---|
| row_number | CSV上の行番号 |
| column_name | エラーが発生した列名 |
| error_code | エラーの分類コード |
| error_message | エラー内容 |
| value | 検査対象となった値 |

### エラーコード

| エラーコード | 内容 |
|---|---|
| REQUIRED | 必須項目が空欄 |
| PRIMARY_KEY_EMPTY | 主キーが空欄 |
| PRIMARY_KEY_DUPLICATE | 主キーが重複 |
| INVALID_DATE | 日付が不正 |
| INVALID_INTEGER | 整数として不正 |
| MAX_LENGTH | 最大文字数を超過 |

## 8. 終了結果

検査終了後、次の内容を画面へ表示する。

- 読み込んだ件数
- エラー件数
- 検査結果ファイルの保存場所

終了コード：

| 終了コード | 意味 |
|---|---|
| 0 | エラーなし |
| 1 | データ検査エラーあり |
| 2 | ファイル読込や設定などの処理エラー |

## 9. テスト方針

`pytest`を使用し、少なくとも次を確認する。

- 正常なデータではエラーが発生しない
- 必須項目の空欄を検出できる
- 主キーの重複を検出できる
- `19650229`を不正日付として検出できる
- `19640229`を正常な日付として判定できる
- 数字以外を整数エラーとして検出できる
- 最大文字数超過を検出できる

## 10. セキュリティ上の方針

- 実際の自治体データを使用しない
- 個人情報を登録しない
- 実在するテーブル名や仕様書を公開しない
- パスワードや接続情報をGitHubへ登録しない
- サンプルデータは架空であることを明記する
